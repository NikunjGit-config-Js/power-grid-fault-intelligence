# Power Grid Fault Detection and Classification

## Problem Statement

Electrical faults on transmission lines must be detected and classified rapidly to prevent equipment damage, maintain grid stability, and ensure public safety. Manual inspection is slow and error-prone; automated systems that can classify fault types from raw current and voltage measurements enable faster response times and more reliable grid operation.

## Why Power-Grid Fault Classification Matters

Transmission-line faults can escalate from minor insulation failures to catastrophic equipment damage within cycles. Accurate, automated classification of fault types (line-to-ground, line-to-line, three-phase, etc.) allows protective relays to isolate the affected segment without shutting down the entire grid. The six fault classes in this dataset represent the most common failure modes in three-phase power systems.

## Dataset

The dataset is generated by simulating a power system in MATLAB with four generators (11 kV) and transformers. Faults are injected at the midpoint of a transmission line. Line currents and line voltages are recorded under normal and fault conditions.

## Problems Identified in Original Pipeline

1. **Preprocessing leakage:** MinMaxScaler was fitted on the entire dataset before splitting. This leaks test-set statistics into training, producing optimistically biased accuracy estimates.

2. **Missing scaler/encoder artifacts:** The shipped models rely on a MinMaxScaler and LabelEncoder that are not saved. They must be reconstructed by refitting on the full dataset at runtime.

3. **Deep-learning model is not CNN-LSTM:** `DL_model.pkl` is a Dense MLP (27 -> 128 -> 64 -> 32 -> 6 with BatchNorm + Dropout 0.5), not a CNN-LSTM as claimed in the original README. It achieves 38.53% accuracy, collapsing toward predicting class 0 for most inputs.

4. **Questionable class names:** Code `1001` is named "Line-to-Line AB" (actually single line-to-ground); code `0110` is named "with Ground" (G=0).

## Physics-Informed Feature Engineering

Instead of the blind polynomial expansion (which generates 27 features of mixed physical meaning), this project implements physics-informed features grounded in power-systems theory:

| Feature | Formula | Physical Meaning |
|---------|---------|------------------|
| I0 | (Ia + Ib + Ic) / 3 | Zero-sequence current (ground fault indicator) |
| Ialpha, Ibeta | Clarke transform | Rotating-frame current components |
| Imag | sqrt(Ialpha^2 + Ibeta^2) | Current magnitude |
| V0, Valpha, Vbeta, Vmag | Same for voltage | Voltage equivalents |
| Za, Zb, Zc | Vx / (Ix + epsilon) | Per-phase impedance (guarded division) |
| I_max, I_mid, I_min | Sorted current magnitudes | Current symmetry features |

Guarded impedance uses a fixed epsilon (never derived from data) to avoid division by zero.

## Polynomial vs Physics-Informed Experiment

A controlled experiment compared feature sets using the same DecisionTreeClassifier (random_state=42) on the same 70/15/15 split:

| Feature Set | Features | Val Macro F1 | CV Macro F1 (mean +/- std) |
|-------------|----------|--------------|---------------------------|
| A (Raw) | 6 | 0.8294 | 0.8412 +/- 0.0074 |
| B (Polynomial) | 27 | 0.8466 | 0.8512 +/- 0.0118 |
| C (Physics Core) | 17 | 0.9925 | 0.9901 +/- 0.0041 |
| D1 (Physics + Current Sym) | 20 | 0.9915 | 0.9949 +/- 0.0018 |
| D2 (Physics Full Sym) | 23 | 0.9945 | 0.9944 +/- 0.0019 |

**Result:** Physics-informed features (D1, 20 features) outperform polynomial features (B, 27 features) by a wide margin while using fewer dimensions. D2 (23 features) achieved a slightly higher single-validation Macro F1 (0.9945 vs 0.9915), but D1 had the stronger cross-validation result (0.9949 +/- 0.0018 vs 0.9944 +/- 0.0019) used for downstream selection, and is also smaller and more compact (20 vs 23 features). D1 was chosen based on cross-validation robustness rather than a single validation split.

## Neural Network

The deep-learning track uses a Dense MLP (not CNN-LSTM) with the following architecture:

- Input: 20 features (D1)
- Hidden layers: 128 -> 64 -> 32 neurons with BatchNorm + Dropout 0.5
- Output: 6 classes with softmax

The MLP achieves 98.07% Macro F1 in Test 4 (nested CV), significantly below the tree-based models. The high dropout rate (0.5) on a relatively small network (14,566 parameters) likely contributes to underfitting.

## Experiment Protocols

| Test | Description | Split Method | Tuning |
|------|-------------|--------------|--------|
| Test 1 | Default models, single split | 70/15/15 stratified | None |
| Test 2 | Optuna tuning on holdout | 70/15/15 stratified | Optuna (5 trials) |
| Test 3 | 5-fold stratified CV | 5-fold CV on dev set | None |
| Test 4 | Nested CV + tuning | 5-fold outer x 3-fold inner | Optuna (10 trials) + Keras Tuner |

The progression adds methodological rigor: Test 1 provides a quick baseline, Test 2 introduces tuning but retains single-split evaluation, Test 3 removes split-optimism via cross-validation, and Test 4 combines nested CV with per-fold tuning for unbiased evaluation.

## Metrics

All metrics are reported as mean +/- std across folds where applicable:

- **Accuracy:** Overall correctness
- **Macro F1:** Unweighted average of per-class F1 scores (primary selection metric)
- **Balanced Accuracy:** Average recall across classes
- **Cohen's Kappa:** Agreement beyond chance
- **Fault Detection Recall:** Recall on fault classes (excluding No Fault)
- **False Alarm Rate:** Proportion of No Fault samples incorrectly classified as fault
- **Per-class precision/recall/F1**

### Near-Perfect Scores Caveat

The top tree-based models achieve Macro F1 > 0.99 across all four experimental protocols. Investigation found:

- No exact duplicate rows (checked on all columns and on the six features alone) and no target leakage found
- Zero false alarms for 4 models across all 5 outer folds
- Consistent performance between default (Test 3) and tuned (Test 4) configurations

Near-duplicates were **not** measured. Simulation rows from the same fault event are likely
consecutive, highly similar time samples; a random stratified split can place such neighbours in both
training and test sets, which would inflate scores. A contiguous-block split would test this and has
not been run.

These results likely reflect **simulation-driven class separability** in the MATLAB-generated dataset. Simulation data often exhibits deterministic signal structure and clean class boundaries that real-world data would not have. The locked final-test evaluation confirms this pattern with perfect scores, but real-world applicability remains to be validated.

## Limitations

1. **Simulation data only:** The dataset comes from MATLAB/Simulink simulations, not real-world measurements. Real transmission-line faults involve noise, measurement error, variable fault impedance, and environmental factors not captured in simulation.

2. **Perfect test scores:** The locked final-test evaluation achieves perfect scores across all metrics. While this indicates strong class separability in the feature space, it may not generalize to real-world conditions.

3. **Preprocessing leakage in legacy models:** The shipped legacy models (decision_trees_model.pkl, random_forest_model.pkl) were trained with a scaler fitted on the full dataset. The production pipeline (LightGBM) avoids this issue.

4. **Questionable class names:** Two fault class labels are inherited from the original notebook and may not accurately describe the physical fault types.

5. **No real-time inference:** The Streamlit demo runs inference locally. For production deployment, a proper serving infrastructure would be needed.

## Future Work

1. **Validate on real-world data:** Test the pipeline on measured fault data from actual power systems to assess generalization.

2. **Investigate class name accuracy:** Verify the physical meaning of fault codes `1001` and `0110` against the simulation model.

3. **Online learning:** Explore incremental model updates as new fault data becomes available.

4. **Edge deployment:** Optimize the pipeline for deployment on edge devices (e.g., protective relays) for real-time fault classification.

5. **Multi-modal fusion:** Combine current/voltage measurements with other signals (e.g., temperature, vibration) for more robust classification.
